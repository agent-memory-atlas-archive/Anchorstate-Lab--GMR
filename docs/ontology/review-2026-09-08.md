# GMR 未来架构审查 rev3（2026-09-08）

本文是对 rev2（2026-09-07 目标架构）的修正稿。方法：先实测当前系统，再由三个独立视角（知识表示/本体论、协议与 token 经济、对抗式系统架构）各写一份审查，最后裁决分歧。三份原始审查与实测样本在本文末尾列出路径。标记：[M] 今日实测，[C] 从代码推得，[O] 判断。

---

## 0. 结论

1. **三层分解的说法错在命名，不在方向。** "memory 层 = 本体" 把 TBox 和 ABox 混了：本体是 schema，记忆是填进 schema 槽位的实例。"fact 层 = KG" 把两种 ABox 混了：探针读出来的（可重算、闭世界）和 agent 断言的（有作者、开世界、需要来源）。"anchor 层 = 状态机" 是一个 JTMS 的 justification 链接穿了状态机的外衣：它真正算的只有一件事，"这条断言依据的读数变了没有"。正确的分法是**一张图，两类来源，一种时效标记**。
2. **MSIS 不是伪命题，但它是类型级的。** 动作签名定义的是 "modify 一个 Function 需要哪些关系"，对最坏实例充分，对具体实例不保证最小。它可审计：任务失败要么是网缺边，要么是签名缺关系。这个审计回路才是收敛机制，比 "agent 顺手更新" 强得多。
3. **当前系统的信封问题是结构性的，不是序列化选错了。** 一次 `read --json` 的 18,564 字节里 9,265 字节是规则表，而规则表由 `shape: contract` 这一个词生成，847 个锚的规则表逐字相同 [M][C]。信封问题就是状态机设计的成本直接落到 token 上。
4. **本地状态 473 MB 与三层互连无关。** 跨层链接只占 450 KB；膨胀来自 journal 里 75% 的 "still"（什么都没变）行，以及 survey 索引把整份文件正文塞进 callee 列 [M]。"空间复杂度高" 的担忧成立，诊断错了。
5. **约 75% 的现有代码在目标架构下没有位置。** 表达式语言、规则表、Warrant/Holding/Shown、said/ground、sync/bindings、links、atlas、adopt、sealed、doctor 的 22 个桶、survey 索引、name-map、http/sql 传输、mem0/claude-code 提供者。这需要 owner 决定，因为 CLAUDE.md §1 的第 1、7、8、10、13 条描述的正是被撤掉的机器。

## 2. 三个直接回答

### 2.1 fact = KG，anchor = 状态机图，memory = ontology，合适吗

不合适。正确的分层：

| 层 | 是什么 | 谁写 | 从现状保留 |
|---|---|---|---|
| 本体（TBox） | 类型、槽位、关系类型（每种标 observed 或 asserted）、动作签名、完备性规则、写入规则 | 人 | coding-v1.yaml，需修 5 处（§4） |
| 观察 ABox | 探针读出的结构关系与读数：calls、contains、签名、body hash | 探针，按文件 hash 局部重算，**只在本地，不进 git，agent 不写** | ast/prose/addr 提取器，fact address |
| 断言 ABox | 槽位值与断言关系，每条是一个 nanopub：断言 + 来源 + 发布信息 | agent 或人，经 `write` 校验 | 197 篇笔记的可入槽部分，Decision/Policy，Claim |
| 身份 | 实体 id 跨重命名、移动、签名变化稳定，由解析器维持 | 机械 | 提取器的 file→kind→name→shape 解析器 |
| 标记 | 每条断言的 IN/OUT：依据的任一读数变了即 OUT；人的 accept 只是对 decided 来源的重新标记 | 机械 | `v` 向量的语义，不保留其存储 |

锚作为持久的、以坐标为中心的对象消失，变成断言上的 (身份, 依据地址, 标记) 三元组。journal 保留为读数缓存和写入日志。"推论" 并入断言 ABox：author = agent、无 reviewed 来源的断言就是 Claim，rev1 的 Claim 已经是这个东西。

### 2.2 MSIS 是不是伪命题

形式化：任务类型 τ 有签名 Σ_τ，`C_Σ(e)` 是从实体 e 出发沿 Σ 的最小不动点。`C_Σ(e)` 对实例 (τ, e) 充分，当且仅当正确输出是 `C_Σ(e)` 的函数。成立需要四个条件，每个都对应今天的一个缺口：

1. **局部性**：任务的每种信息依赖都是 Σ 里的一种关系。缺一种关系就静默失败。今天缺的是 Concept（§2.3）。
2. **沿 Σ 的完备性**：图是开世界，没有 governed_by 边意味着 "没人写"，不是 "没有"。MSIS 需要负信息：按实体按关系的完备性声明，"X 的 governed_by 截至读数 R 是完整的"。v1 没有。这正是 owner 说的幻觉触发点：模型分不清 "无" 和 "未记"。
3. **有界扇出**：hub 让闭包平方增长。截断必须显式，`…+37 Function realize this Concept`，不能像 doctor 的 never_asked 那样静默。
4. **粒度匹配**：38 篇笔记 about 一个文件，而 modify 作用在函数粒度；粒度错了闭包要么全给要么不给。

所以 problems.md §零 说 "GMR 不算 MSIS" 和 rev2 说 "动作签名就是 MSIS 定义" 都对，量词不同：`MSIS(τ,e) ⊆ C_{Σ_τ}(e)`，enter 交付类型级充分集并标注完备性与截断，声称对 τ 充分，从不声称最小，由 agent 收窄。Σ_τ 本身用经验校验：usage 与 saw 记录已经记下交付了什么、引用了什么，签名里从未被任何 modify 任务引用的关系被剪掉。这就是可测的收敛指标。

还有一条不在本体里的约束 [M, problems.md §八]：同一条信息在 agent 形成计划之前到达是重定向，之后到达是脚注。enter 必须在任务开始时由 hook 触发，否则 MSIS 无意义。

### 2.3 A、B 模块的业务关系在本体里是什么

仓库内的现成病例 [C]："已关闭的锚不被观察" 这一规则在 7 个 verb 文件的 10 处各写一份，没有共享函数，没有依赖边；problems.md §六 已经测到三个 verb 对它意见不一。

这在知识表示里是 **Concept** 节点：`Concept:live-anchor`，定义 "未关闭且非终态的锚"，关系 `realizes: Function → Concept`。Policy 从此 about 一个 Concept，而不是 about 十个 Function。共变是 Datalog 推论，不是断言：

```
must_change_with(X,Y) :- realizes(X,C), realizes(Y,C), X != Y.
must_change_with(X,Y) :- consumes(X,F), produces(Y,F).
```

emergence 实验里长出来的 exporter→reporter 边，本体里是 Format:ledger-line 的 produces/consumes；v1 已有这个机制。v1 缺的是**共享物既非数据形状也非规则时的命名**：Concept、realizes、Policy.about → Concept。`enter(modify, status.rs#run)` 沿 realizes → Concept → realizes⁻¹ 两跳拿到另外九处，深度 5 找不到的问题在两跳内解决。`must_change_with` 保留为兜底，必须带 reason；同一 reason 第二次出现时，write 提示把它命名为 Concept。

## 3. 目标生态与 GMR 定位

**生态。** 一族本体：核心本体（Policy、Decision、Claim、Incident、Owner、Concept、supersedes、contradicts、rests_on）加领域本体（coding、trading……）。每个仓库或组织一张网，网随仓库走（进 git），读数缓存本地可删。任何厂商的 agent 都能写，因为写入被本体机械校验而不是被 prompt 约束。跨仓库：实体住在所有者仓库，边存在起点侧，外键 `repo@path#name`，rests_on 指向已发布产物（schema 文件、包版本、git sha）的读数，绝不指向别人的工作树。非代码事实：script 探针读的实体（市场、注册表）或 user-said 且无探针的实体，后者只靠 supersedes 失效。无法执行槽位规则的外部记忆库（mem0、claude-code）不是网的来源，只是 rests_on 的目标。

**GMR 的产品边界，四件事，前三件可以不跑 runtime 单独交付：**

1. 本体格式与校验器。
2. 网文件格式与写入协议：槽位、CAS、来源、噪音拒绝。
3. 时效契约：fact address 的 `A(outcome, d)` 加探针契约。
4. 每仓库一个 runtime：locate / enter / check。

不是存储引擎，不是检索器，不是模型，不是 CLI。

**ATA 会怎么用。** ATA 的提交是 `evidence → sub_thesis → main_thesis` 的 DAG，带 EvidenceSource 与 EvidenceMetric，这就是 Claim 图加 rests_on。ATA 固定三个 API 面并明令禁止第四个，所以 GMR 在 ATA 里是 submit 内部的无 IO 库，不是服务：ATA 自己的本体（Instrument、Thesis、Evidence）、一个行情 script 探针、submit 时 write 并为每条证据算 rests_on、evaluation 时 check 说出哪些读数动了。这需要一个无 IO 的 `gmr-net` crate，只做寻址与校验。

## 5. 协议

### 5.1 wire 语法，读写共用

```
@Type key [=addr] ~s      节点；=addr 是读数地址，8 位 hex
slot: text ~s             行首 ! 表示其依据读数已变
>rel Type:key ~s          出边；<rel 入边；缩进行是对端节点的槽位
~s who how address [!stale axes @seq]   来源，每种只写一次，放页脚
```

JSON 每个字段付 4 个以上 token 的标点且重复键名；YAML 作写入格式有歧义；Markdown 没有语法，196 篇笔记就是它产出的东西。行语法用 split 就能解析。

`enter(modify, carry_linked)` 的完整示例 1,094 字节，信封 154 字节即 14%，其中 stale 标记是今天样本里真实的 `holding=moved @62437`：

```
@Function crates/gmr-runtime/src/memory.rs#carry_linked =fcfcce7f ~a
purpose: carries records linked from an already-delivered memory into the answer, one hop, when asked. ~a
!contract: gated by Instructions.carry; narrows a slice of the caller's total Budget per record and mints no total of its own. ~a
fails_by: a store call that outruns its slice is reported unreachable, never dropped silently. ~a
>reads Field:crates/gmr-runtime/src/read.rs#Instructions.carry ~a
>governed_by Policy:content-budget ~b
 claim: one operation has one content total; every walk narrows a slice of it.
>decided_by Decision:carry-one-hop ~b
 claim: relevance beyond one hop is the domain's judgment, not the substrate's.
 ask: does the new code recurse past one hop, or walk without carry being asked?
>verified_by Test:crates/gmr-runtime/tests/grounding.rs#carrying_linked_records_is_asked_for_and_they_come_back_marked ~a
<calls Function:crates/gmr-runtime/src/read.rs#ground ~p
~a agent task-0912 observed fcfcce7f@61850 !stale sig,body @62437
~b human zongming decided 2026-08-22
~p probe callers,tests now
```

18,564 → 1,094 是 17 倍。加 `%prefix` 头做相对键约 850 字节。

### 5.2 写入

`gmr write < doc`，同一语法，多块一文档，原子。校验顺序：类型存在且键形合法；事实键实体**现在**路由到探针，未命中为 unresolved；槽位已声明且 required 齐全；来源对该槽位合法，Decision.claim 只接受 decided 且 human；observed 必须引用本库本任务发过的地址；one_sentence；关系类型存在且两端类型匹配，must_change_with 必带 reason，supersedes 指向同类已有目标；然后过 9 条噪音检查。回复 ≤ 200 字节：

```
+ Decision:carry-one-hop
+ Decision:carry-is-opt-in
+ Decision:carry-shares-budget
+ Function:…#carry_linked.contract @62501
+ 4 edges
```

拒绝形如 `! line 7 one_sentence`，exit 2，什么都不写。警告落地，exit 1。

写入单元是 nanopublication：一条断言（一个槽位值或一条关系，或关于同一实体的一小组）+ 来源 + 发布信息。不是三元组（没有来源），不是笔记（是捆）。runtime-carry-linked.md 迁移后是三个 Decision 加一个 contract 槽位加两条边，1,597 字节进、137 字节出，对比 2,853 字节笔记加一次 sync。迁移试验把它压成一个 D 是漏算，笔记里有三个可分的判断、三个 review question。

噪音检查九条，覆盖迁移试验的四类丢弃：单终止符且 ≤ 240 字符；历史词表 used to / once / previously / no longer / briefly / originally；ISO 日期与 `\d+ ?(ms|KB|MB|%|of \d+)`；`[[…]]`、`](`、"see "；≥ 40 字符与实体源码重合或 > 2 个反引号段；反引号标识符必须在实体读数里或能解析为键（这一条会抓到笔记里 `grounded: false` 那句从写下起就错的话，作警告）；claim 里的 we / I / probably / seems；claim 里的 because / so that / since；与已有槽位 stem-Jaccard ≥ 0.8 且无 supersedes。抓不到的：来源合法的一句话假合同，那是 entailment。

### 5.3 载体

本体文件本身就是接口，SKILL.md 从 28 KB 缩成 1,535 字节的入口卡（scratchpad/entry-card.md），CLAUDE.md §2 与 §3 各成一个 Policy 节点。两个条件：动作签名必须可执行，`calls⁻¹ | reads⁻¹`、"governed_by of every contains⁻¹ ancestor" 今天是解析器跳过的注释，需要一个六算子路径语言（rel、⁻¹、|、->、*、filter）让 enter 成为它的解释器；没人预先加载本体，enter 报槽位名，拒绝报规则，`read ontology.Type` 答其余。固定成本 10k token → 380 token。

### 5.4 动词

| 动词 | 输入 | 输出预算 | exit | 吸收 |
|---|---|---|---|---|
| locate | 词、path#name、path:line | ≤ 5 行 ≤ 400 B | 0 命中 1 无 2 错 | memories、links、atlas、status 列表 |
| enter | action、key | ≤ 4 KB，信封 ≤ 20% | 0 / 1 有 stale / 2 unresolved / 3 无此 action | read --carry、status key、check key、sample、observe、ground --reach |
| read | key 或 ontology[.Type] | ≤ 1 KB，不遍历 | 0 / 2 | read、since、health |
| write | stdin 文档 | ≤ 200 B | 0 / 1 警告 / 2 拒绝 | anchor -m、said、bind、attest、reaffirm、cobound、link、condense、accept --why、close、revise 族 |
| check | 无、key、--since、--task | 每 stale 项 ~100 B，安静时零输出 | 0 / 1 stale / 2 探针失败 | check、observe、pass、ground、doctor、sync |

每个退役的动词都在删一份第二拷贝：said/ground 是读数旁边的不变式副本；accept --why 与 revise 族手驱一张 shape 生成的规则表；sync 是 frontmatter 的编译副本；condense、atlas、adopt 各是一个视图或导入器。init、probes、export、import、publish 作为操作员引导保留但隐藏。

## 6. 收敛规则与指标

rev2 的单一机制不够，攻击面五个：没人删稳定代码上的错 Claim；"完备性随任务增长" 是单调的，Claim 按 task seq 只增；槽位无 supersede，两个 agent 写同一槽位是 git 冲突或静默覆盖；hub 无上限，38 篇笔记 about read.rs，enter 要读全部；stale 清除率靠复述或 retire 就能刷高。

不需要 worker 与判官的最小规则集：

- **R1 槽位身份**：(实体, 槽位) 一个值；写即替换，旧值进日志。
- **R2 关系身份**：(kind, from, to) 唯一；重写只更新来源。
- **R3 CAS**：写入携带它所替换值的 hash，不匹配即拒绝。矛盾变成 "你没读当前值"。
- **R4 上限**：one_sentence ≤ 200 B；Claim.text ≤ 300 B；每实体 ≤ 5 条活 Claim、≤ 8 条 must_change_with，第六条写入强制先退一条。
- **R5 reason 必填**：must_change_with、contradicts、rests_on any。
- **R6 读即投票**：一条 Claim 在其实体后续 K 次 enter 里未被交付并保留，退出交付，进日志不删。唯一的收缩机制。
- **R7 stale 阻塞完成**：enter 交付 stale 项与 diff，该任务的 write 在每项被重新证实或退役前拒绝。唯一的清除机制。
- **R8 指标**：交付的 stale 项里重新证实 / 改写 / 退役的分布；agent 首次写入前在交付子图之外读的字节数。后者不随任务下降，就没有在收敛。

加本体侧的两条：签名里从未被引用的关系剪掉；每实体每关系的 complete 声明是负信息，enter 原样交付。

## 8. 实施路径

**Phase 0，本月，不写代码，证伪实验。** 手写 read.rs 子系统的网，约 40 个实体，它的 38 篇笔记按 §5 迁移。跑 10 个真实任务各两次：一臂拿手工序列化的 `enter(modify, X)` ≤ 4 KB，另一臂拿今天的 `read --json` 加 SKILL.md。测：首次编辑前在交付集之外读的字节数、测试通过率、任务结束时的写入是否无提示地填进槽位。**证伪条件**：子图臂在交付集之外读的量与对照臂相当，或不到 50% 的写入无判官即入槽。

**Phase 1，网与写入。** 新增 gmr-net：格式、校验器、CAS 写入、本地索引。删 sync/memories/notes、bindings、links、atlas、adopt、said/ground、expr、shapes、survey 索引。验收：write 拒绝无槽位文本；197 篇笔记迁移完成并测出丢弃率。

**Phase 2，enter 与 check。** 动作闭包、反向索引、读数缓存取代 journal。删 Warrant/Holding/Shown、sealed、22 个 doctor 桶。验收：enter p90 ≤ 4 KB 且 ≤ 50 ms；提交后的 check 是 O(触及文件数)。

**Phase 3，locate 与生态。** 混合 locate、外键、结构边解析器、可嵌入 crate。验收：ATA submit 写入带 rests_on 的 Claim；check 说出哪些证据的读数动了。

hook：任务开始 enter，任务结束 write + check。channel 与 emergence 的 fixture 保留为回归，Phase 2 后重跑 channel A1 与 A1′，criterion 2 应翻转，V(A1) 预期几 KB。

## 9. 三份审查的分歧与裁决

| 分歧 | 本体论 | 系统 | 协议 | 裁决 |
|---|---|---|---|---|
| 键 | 不透明 id | path#name，每源文件一个 net 文件 | wire 用 path#name | 存储身份用 id，wire 显示 label，解析器维持映射；net 文件按源文件分，git 的 rename 检测处理移动 |

| 结构边 | 观察 ABox，探针物化 | 读数，本地，不进 git | enter 里 `~p probe now` | 一致：readings，不是 relations |
