# Migration: all 196 notes against coding-v1

Every note under `memories/` was mapped onto the slots of `coding-v1.yaml` by four independent passes (49 notes each), one JSON row per note, relation names checked against the ontology. The per-note table is at the end; the aggregate is here.

## Verdict

The slots hold. 131 notes fit as written, 52 fit but are about machinery the target design retires, 13 need a slot or entity the ontology lacks, none is unmappable. The notes decompose into 714 Decisions and Policies (175 Policies), 499 slot values and 1,049 edges; 305 of the Decisions carry a review question. A quarter of the text on average fills no slot and is dropped: cross-references written as prose (130 notes; these become edges), history (96), restated code (46), dated measurements (31).

Edges by kind: decided_by 337, verified_by 162, rests_on 162, governed_by 132, must_change_with 111, caused 34; structural kinds written by the passes (calls, reads, produces, consumes, contains, implements, imports) 111 in total. Under rev3 the structural kinds are readings, not assertions, so those 111 would not be written by hand; the verdict does not depend on them.

## Method limits

Four passes, one model each, calibrated on the sixteen-note trial; no pass was checked by a second pass. The fit verdicts are therefore one reading per note. The trial's own miscount (one Decision where the protocol review found three in runtime-carry-linked) shows the split is sometimes under-counted; the 714 is a floor.
